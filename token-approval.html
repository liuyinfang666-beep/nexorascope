Understanding Token Approvals

Learn what smart-contract permissions allow, why broad approvals deserve attention, and how to review an allowance or NFT operator permission before taking action.

Independent educational guide · Last reviewed November 17, 2026

In this guide: ERC-20 allowance · Unlimited approvals · NFT permissions · Review safely · Revocation limits

1. What is an ERC-20 token allowance?

An ERC-20 token contract can let a token holder authorize another address (the spender) to transfer up to a specified amount of tokens on the holder’s behalf. The holder commonly grants this permission through the token’s approve(spender, amount) function. The allowance can then be queried by the token contract using allowance(owner, spender).

The spender is often a smart contract used by a decentralized exchange, lending protocol, bridge, or other application. Approval does not itself transfer tokens, but it grants a permission that the spender may use according to the token contract’s behavior. The exact implementation and current state matter.

2. Why can unlimited approval increase exposure?

Some interfaces request a very large allowance, often described as “unlimited,” to avoid asking the user to approve again for later interactions. On standard ERC-20 implementations, a very large allowance can remain available until it is spent or changed. If the spender contract is malicious, compromised, or has dangerous behavior, an excessive allowance can expose more tokens than the user intended for a single action.

Risk depends on the token contract, spender contract, chain, and current allowance. An allowance does not prove that a contract is malicious, and a large allowance alone does not prove that funds have been taken. It is a permission worth understanding and reviewing.

Practical principle: When an application supports it, consider approving only the amount needed for the intended action rather than granting a broad allowance. Check the wallet and application documentation because interfaces and token behaviors differ.

3. How are NFT approvals different?

NFT standards expose different permission patterns. Under ERC-721, a token owner may approve an address for a specific token ID or approve an operator for all tokens owned by that account within a collection. ERC-1155 uses operator approvals that can apply to multiple token types held by an account. The actual permission depends on the standard and contract implementation.

Do not assume that an NFT approval is limited to one item: inspect whether the permission is token-specific or collection-wide, identify the operator, and verify the collection contract and network.

4. How to review an approval carefully

  1. Choose the correct network. Ethereum mainnet and Ethereum-compatible networks maintain separate contract state. Make sure you are checking the chain where the approval was made.
  2. Identify the token or collection. Confirm the token contract address or NFT collection address using an independently verified project source or reputable block explorer.
  3. Identify the spender or operator. Compare the address with the application’s official documentation. A familiar name or logo in a user interface is not sufficient proof.
  4. Read the permission scope. For ERC-20, check the allowance amount and token decimals. For NFTs, check whether approval is token-specific or operator-wide.
  5. Consider whether you still need it. An old approval may be unnecessary, but some applications rely on existing permissions for future actions. Understand the effect before changing it.
  6. Verify the transaction before signing. If you choose to reduce or revoke an allowance, confirm the network, token contract, spender, requested new value, wallet account, and gas fee.
  7. Check the result independently. After a confirmed transaction, refresh a trusted permission-review tool or block explorer and verify the allowance or operator status on the same network.

Use a reputable permission-review tool reached through a source you independently trust. Do not follow unsolicited links from social media or direct messages. Never enter a recovery phrase or private key into an approval checker. A permission review should not require those secrets.

5. What revoking can and cannot do

Revoking or reducing an approval generally changes what the spender can do in the future under that permission. It does not reverse token transfers that already happened, recover stolen assets, or guarantee that no other permission exists. A separate approval may exist on another network, for another token, or for another spender.

Revocation is an on-chain transaction and usually requires the network’s native asset to pay gas. Until the transaction is confirmed, the old permission may remain active. If a spender has already used an allowance, revoking it cannot undo that transfer.

Disconnecting a wallet from a website is not the same as revoking an on-chain approval. The website connection and the token contract permission are separate mechanisms.

6. Common approval-review mistakes

  • Checking the wrong network or a look-alike token contract.
  • Assuming a project name or verified-looking logo proves the spender address is safe.
  • Confusing a displayed token amount with the raw integer amount stored by a contract.
  • Assuming “revoke” will recover assets already transferred.
  • Signing an unfamiliar transaction just because a site labels it “security check.”
  • Sharing a recovery phrase with a tool or person claiming to scan approvals.

Frequently asked questions

Does disconnecting my wallet remove token approvals?

No, not by itself. Disconnecting normally ends or removes a site connection. An on-chain allowance or NFT operator permission is separate and must be checked on the relevant network.

Is every unlimited approval a scam?

No. Some legitimate applications request large allowances for convenience. However, a broad allowance can increase exposure if the spender is compromised or malicious, so understand the spender and permission scope.

Does revoking an approval recover tokens already taken?

No. Revocation changes a permission going forward after the transaction is confirmed. It cannot reverse completed transfers or recover stolen assets.

Do I need to pay gas to revoke an approval?

Usually yes. Revoking or changing an on-chain permission is generally a transaction on that network and requires its native asset for gas. Check the wallet’s transaction preview before signing.
